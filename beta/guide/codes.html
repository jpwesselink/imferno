    Validation Codes#

    Every finding names the rule it reports and the edition of the spec that was applied, as a code like ST2067-3:2016:7.2.2/SegmentDuration. Use the rule ids and codes to configure rule severity.

    #Code format

    <SPEC>:<EDITION>:<CLAUSE>/<Name>
    PartMeaning
    SPECSMPTE document, e.g. ST2067-2, ST429-9. IMFERNO for engine checks with no SMPTE source; XSD for schema validation.
    EDITIONThe edition of the spec that was applied (2013, 2016, 2020, …). For XSD the schema used (CPL-2016); omitted for IMFERNO.
    CLAUSEClause of that edition the rule comes from (7.2.2, A.2). For IMFERNO a group (Package, Mxf).
    NameThe rule's name, unique within the spec.

    Each rule has a stable rule id SPEC/Name (e.g. ST2067-3/SegmentDuration) that does not change when a clause is corrected; the clause and severity of each edition live in the rule's edition table below.

    In the tables, each edition column shows the clause and default severity. — means the edition does not contain the rule. ✓ marks a row checked against that edition's text; † a clause known or suspected to be wrong. Unmarked rows are carried over from earlier catalogues and not yet checked.
