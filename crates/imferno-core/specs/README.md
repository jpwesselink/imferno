# SMPTE XML schemas

Vendored copies of the SMPTE XML Schema (XSD) documents that imferno's
catalogue mirrors. Source: <https://smpte-ra.org/ns>.

## License

Each XSD carries the SMPTE BSD-style license in its header comment
block. Redistribution in source form is permitted provided the
copyright notice is retained — these files are checked in unmodified
so the notice is intact.

## Known gaps

SMPTE-RA does not publish the following XSDs at
`https://smpte-ra.org/sites/default/files/`. They are referenced as
namespace imports by the schemas above but the XSD documents
themselves are not directly fetchable from the public web index.
Source: the SMPTE standard PDF or the IMFTool / regxmllib community
mirrors.

| Missing | Why we'd want it |
|---|---|
| ST 433:2008 — `dcmlTypes` | Imported by every CPL/PKL XSD (`xmlns:dcml`). Without it XSD validation cannot resolve `dcml:RationalType`, `dcml:UUIDType`, `dcml:UserTextType`. |
| ST 429-9:2014 — Volume Index | The VOLINDEX/ASSETMAP schema. Index page is empty. |
| ST 2067-9:2018 — SCM | `/schemas/2067-9` returns 404. |
| ST 2067-201:2019/2021 — IAB | `/schemas/2067-201` returns 404. |
| ST 2067-202:2018 — ISXD | `/schemas/2067-202` returns 404. |
| ST 2067-21:2020/2023/2025 — newer App #2E editions | Only the 2016 edition is published under `/schemas/2067-21`. |

For runtime XSD validation to work end-to-end on a CPL we also need
`dcmlTypes` from the imports. Two options to source it:

1. Extract it from a downloaded copy of the ST 433:2008 PDF (the XSD
   is published as a normative annex).
2. Use the IMFTool repo's vendored copy
   (`https://github.com/IMFTool/IMFTool/tree/master/src/xml-schemas/`)
   under the same SMPTE BSD license.

Until `dcmlTypes` is vendored, XSD validation can be configured to
treat unknown imported namespaces as opaque (lax validation mode in
libxml2).
